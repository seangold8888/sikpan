# 일반식당 확장 기획 — 걸어갈 수 있는 식당까지 한 랭킹에

2026-09-11. 사용자 결정 반영. 같은 날 카카오 정책 확인으로 목록 출처를 공공데이터로 바꿈.

## 왜

구내식당은 메뉴가 매일 바뀌어 "오늘 메뉴로 매긴 점수"가 성립한다. 일반식당은 메뉴가 고정이라
같은 방식이면 순위가 매일 같다 → 목록이지 추천이 아니다. 그래서 추천의 뜻을 바꾼다.

- 구내식당: 오늘 **메뉴가** 좋은 곳
- 일반식당: 오늘 **나에게** 맞는 곳 — 거리·가격·최근 며칠 먹은 것과의 균형

둘을 **한 랭킹**에 세운다. 구내식당 7,500원과 일반식당 9,000원이 같은 가성비 축에서 비교되는 것이
통합의 값어치다.

## 결정 (2026-09-11)

| 항목 | 결정 |
|---|---|
| 구조 | 통합 랭킹 + "구내식당 / 일반식당" 필터. 탭 분리 안 함 |
| 반경 | 기본 도보 10분 ≈ 700m. 선택지 5분(350m) / 15분(1,000m). 기준은 검색한 건물 |
| 메뉴·가격 | **메뉴판 사진 → 기존 OCR**. 카카오·네이버 상세 데이터는 쓰지 않는다 |
| 제외 업종 | 술집·호프, 배달 전문. 카페·패스트푸드는 포함 |

## 유지 원칙

- 숫자로 고른다. 근거와 계산을 보여 준다.
- 모르는 값은 0이 아니라 중립 0.5.
- 메뉴판에 인쇄된 값만. 추정 금지.
- 새 섹션을 만들지 않는다. 카드와 필터 안에서 푼다.

## 규모 (카카오 로컬 API로 한 번 셈, 2026-09-11)

갑을그레이트밸리 기준, 술집 제외. 카카오 정책상 목록은 저장하지 않고 즉시 지웠다 — 아래는 집계 숫자만.

| 반경 | 곳 | 업종 상위 |
|---|---|---|
| 350m | 302 | 한식 111, 카페 57, 중식 36, 일식 27, 분식 14 |
| 700m | 1,013 | 한식 396, 카페 200, 중식 100, 일식 62, 분식 49, 양식 34, 치킨 33 |
| 1,000m | 1,692 | 한식 647, 카페 357, 중식 141, 일식 116, 분식 82 |

OSM 은 700m 26곳뿐이라 쓸 수 없다. **700m 에 1,000곳 넘게 있으므로 가격은 전부 못 채운다** — 사진이 있는
곳부터 점수를 주고, 나머지는 거리·업종만 보인다.

## 데이터

| 항목 | 출처 | 상태 |
|---|---|---|
| 식당 목록·업종·영업상태·좌표 | **서울시 일반음식점 인허가 정보**(`LOCALDATA_072404`) + **휴게음식점**(카페·분식 일부) | 공공누리 1유형(출처표시, 저장·변경·상업 가능). 서울 열린데이터광장 Open API, 인증키 필요 |
| 좌표 | 인허가 데이터의 TM 좌표(EPSG:5174) | 위경도 아님 → 변환 필요(pyproj) |
| 메뉴·가격 | 메뉴판 사진 → `scripts/ocr.py` | 파이프라인 있음. 점심 다니며 입구 메뉴판 한 장씩 |
| 가게 상세·리뷰 | 카카오맵 검색 링크(`map.kakao.com/?q=`) | 링크만. API 결과는 저장 안 함 |
| 영업시간·휴무 | 사진 | 부분 |
| 대기줄·혼잡 | 없음 | 포기 |

**카카오 로컬 API 결과는 저장할 수 없다.** 운영정책 제5조 제20호, 그리고 카카오 Map 담당자 답변
(2026-07-23 서버 1시간 캐시도 불허, 2026-08-26 "기존 저장 데이터는 즉각 삭제", 내부 보관·좌표만 저장·별도
제휴 모두 불가). 그래서 한 번 세어 본 뒤 목록 파일과 수집 스크립트를 지웠다.

**업종 매핑 (인허가 `업태구분명`)**: 한식·중국식·일식·경양식·분식·김밥(도시락)·패스트푸드·뷔페식·
외국음식전문점 … 은 포함. **호프/통닭, 정종/대포집/소주방, 감성주점, 라이브카페** 는 제외(결정: 술집).
치킨집은 인허가상 "호프/통닭"으로 묶이는 경우가 많아 이름으로 보정이 필요할 수 있다.

**배달 전문은 업종으로 못 가린다.** 인허가 데이터에도 홀 유무가 없다. `data/places.json` 처럼 손으로
`delivery_only: true` 를 표시한다.

## 점수 — 일반식당 축

| 축 | 구내식당 | 일반식당 |
|---|---|---|
| 가까움 | 기준 건물 거리 | 같음 |
| 가성비 | 가격, `_price_score` | 대표 점심가, 같은 함수(반경 안 중앙값 기준) |
| 반찬수·메인수·희소성 | 메뉴판 | 없음 → 중립 0.5 |
| **돌려먹기 (신설)** | 적용 | 최근 7일 먹은 업종(한·중·일·양·분식·카페…)과 겹치면 감점 |
| 회피 | 최근 먹은 곳 `ate` | 같음 |

매일 순위가 달라지는 힘 = 돌려먹기 + 회피. 이 둘이 없으면 일반식당 추천은 죽는다.

**가격 없는 1,000곳을 어떻게 세울지**: 가격을 모르는 곳은 가성비 중립(0.5)이라 거리만으로 줄이 선다.
그러면 목록 대부분이 "가까운 순"이 된다. 그래서 기본 화면에는 **가격이 확인된 곳 + 구내식당**만 점수로
세우고, 가격 미확인 곳은 "근처 더 보기"로 거리순 목록에만 둔다.

## 화면

- 검색줄에 반경 선택(도보 5 / 10 / 15분).
- 카드에 배지 "구내식당 / 일반식당" + 업종. 필터로 끄고 켠다.
- 일반식당 카드: 대표 메뉴·가격이 있으면 점수, 없으면 "가격 미확인" + 거리·업종·카카오맵 링크.
- 사진 등록: GitHub 이슈에 사진을 올리면 Action 이 OCR 해 반영(휴대폰에서 바로). 2차.
- 지도: 일반식당은 작은 점. 점수 있는 곳만 이름표.

## 단계

1. **목록** — 서울 열린데이터 인증키 → 금천구 일반·휴게음식점 중 영업 중 + 반경 1km → `data/nearby.json`(공공누리, 출처 표기) + 업종별 개수 리포트.
2. **화면** — 반경 필터, 일반식당 카드(거리·업종·링크만), 지도 점.
3. **가격** — 사진 OCR 입력 경로. 가격 있는 곳부터 점수.
4. **돌려먹기 축 + 통합 랭킹.**
